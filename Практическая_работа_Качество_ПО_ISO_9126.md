**Дисциплина:** качество программного обеспечения.
**Исполнитель:** ________________ (ФИО, группа)
**Дата:** 07.10.2026

**Объект оценки:** корпоративная система (КС) «Анализ себестоимости и прогнозирование брака молочной продукции» — конфигурация платформы 1С:Предприятие 8.3 (имя конфигурации — `АнализСебестоимостиИПрогнозированиеБракаМолочнойПродукции`). ## 1. Краткая характеристика компонентов информационной системы

### 1.1. Программное обеспечение (ПО)

**Платформа и режим работы:**

- Платформа **1С:Предприятие 8.3**, управляемое приложение (`DefaultRunMode = ManagedApplication`), интерфейс **Taxi**, режим совместимости с платформой **8.3.5** (`CompatibilityMode = Version8_5_1`).
- Управляемый режим блокировок данных (`DataLockControlMode = Managed`), язык интерфейса — **русский** (единственный), встроенный язык программирования — русский.
- Клиентские приложения: тонкий клиент, веб-клиент, мобильный клиент (в свойствах конфигурации заявлены мобильные функции: биометрия, резервное копирование ОС).

**Прикладное решение.** Конфигурация «Анализ себестоимости и прогнозирование брака молочной продукции» (версия и поставщик в свойствах не заполнены). Состав — **63 объекта метаданных**:

- **НСИ — 11 справочников:** НоменклатураМолочнойПродукции (цена реализации, тип продукции), Цеха, ТипыЦехов, Бригады, СпецификацииРецептуры, ПричиныБрака, Поставщики, ЕдиницыИзмерения, Сотрудники, ВидыРабот, Склады; **6 перечислений:** ТипыМолочнойПродукции, СтатусыСпецификаций, КатегорииПричинБрака, ТипыСкладов, ЭтапыПроизводстваМолочного, СтатусыЭтаповПроизводства.
- **Документы — 5:** ПоступлениеСырья (партии сырья: количество, цена, срок годности, фактическая жирность), ЗаказНаПроизводство (план выпуска по спецификации; по команде формируются этапы производства), ЭтапПроизводства (план/факт, цех, бригада, статусы, табличная часть «Трудозатраты»), АктОБраке (качественные показатели: фактические и нормативные жирность/кислотность, отклонения, стоимость брака), ВыпускГотовойПродукции (FIFO-списание материалов, расчёт себестоимости единицы продукции).
- **Регистры накопления — 5:** СкладскиеОстатки (партионный учёт: склад, номенклатура, срок годности, номер партии, документ партии), ВыпускПродукции, БракПроизводства, СебестоимостьВыпуска (ресурсы: количество выпуска/брака, стоимость сырья, труда, упаковки, брака, накладные расходы; заданы **агрегаты** и **дополнительный индекс**), ТрудозатратыПроизводства.
- **Регистры сведений — 7:** ПрогнозыБрака, РекомендацииИИ, ТарифыВидовРабот, КачественныеПоказателиСырья, ЦеныНоменклатуры, НормыПроизводства, АналитикаБракаПоМесяцам.
- **Отчётность — 5 отчётов на СКД:** ОтчётПоБраку, ОтчётСебестоимости, ДвижениеНоменклатуры, ПрогнозБрака, ПрогнозПотребностейВСырье.
- **Обработки — 3:** ПрогнозированиеБрака, АнализСебестоимости, Демонстрация_UT.
- **Общие модули — 5:** МатематикаПрогнозирования, АналитикаРисков, ОбщиеФункцииМолочногоПроизводства, РаботаСYandexGPT, UT_МолочногоПроизводства; **константы — 6:** YandexGPTAPIКлюч, YandexFolderID, КоэффНакладныхРасходовПроцент, НормаБракаПоУмолчанию, МесяцевИсторииДляПрогноза, АльфаКоэффEMA; **общие формы — 2, роли — 2, подсистемы — 5**.

**Функциональные возможности (по подсистемам командного интерфейса):**

- **Учёт производства:** приход сырья, заказы, этапы, выпуск, акты о браке. Проведение документов формирует движения по регистрам: ПоступлениеСырья → СкладскиеОстатки; ЭтапПроизводства → СебестоимостьВыпуска, СкладскиеОстатки, ТрудозатратыПроизводства; АктОБраке → БракПроизводства, СебестоимостьВыпуска; ВыпускГотовойПродукции → ВыпускПродукции, СкладскиеОстатки. Предусмотрен контроль достаточности остатков и **FIFO-списание** материалов по партиям (по сроку годности).
- **Прогнозирование брака:** расчёт процента брака по месяцам (история до 24 месяцев), EMA-сглаживание, линейный тренд (МНК), коэффициент детерминации R², среднее квадратическое отклонение (СКО), сезонные коэффициенты (0,80–1,28), прогноз на 6 месяцев вперёд с доверительным интервалом ±СКО, уровни риска (Низкий / Средний / Высокий / Критический / Недостаточно данных), запись прогнозов в регистры ПрогнозыБрака и АналитикаБракаПоМесяцам.
- **Анализ себестоимости:** структура себестоимости (сырьё, труд, упаковка, накладные расходы, брак), сопоставление с ценой реализации, цветовая индикация показателей.
- **ИИ-рекомендации:** модуль РаботаСYandexGPT отправляет запросы в YandexGPT API (модель `yandexgpt-lite`, temperature 0,3, maxTokens 2000, системная роль — технолог молочного производства) и сохраняет рекомендации в регистр РекомендацииИИ.
- **Контроль качества разработки:** модуль UT_МолочногоПроизводства содержит **10 юнит-тестов** (EMA ×2, МНК, R², СКО, сезонный коэффициент, 4 теста уровней риска) и функцию их пакетного выполнения; обработка Демонстрация_UT выполняет все тесты.
- **Разграничение доступа:** роль **Администратор** (полные права по умолчанию) и роль **Аналитик** (197 настроенных прав: просмотр НСИ и документов, чтение/редактирование регистров, запуск 5 отчётов и 2 обработок; **нет прав** на создание и проведение документов).

**Стороннее ПО:** платформа 1С:Предприятие 8.3, ОС Windows или Linux, СУБД (файловая или MS SQL Server / PostgreSQL), доступ в сеть Интернет (YandexGPT API).

### 1.2. База данных (БД)

- **Тип БД:** база данных 1С:Предприятие 8.3 — **файловый вариант** (файл `1Cv8.1CD`) либо **клиент-серверный** (MS SQL Server, PostgreSQL и др. — поддерживаются платформой).
- **Модель данных:** 5 регистров накопления (остатки и обороты), 7 регистров сведений, таблицы 11 справочников и 5 документов с табличными частями. Партионный учёт сырья (номер партии, документ партии, срок годности) обеспечивает FIFO-списание.
- **Производительность:** управляемый режим блокировок; у регистра СебестоимостьВыпуска заданы агрегаты и дополнительный индекс для ускорения отчётных выборок.
- **Целостность:** движения «документ → регистры» реализованы в процедурах `ОбработкаПроведения`; в Акте о браке предусмотрена отмена проведения (`ОбработкаУдаленияПроведения`).
- **Резервное копирование:** штатными средствами платформы (выгрузка ИБ в файл `.dt` либо копирование файла `1Cv8.1CD`); регламент в репозитории не описан.

## 2. Определение критериев качества и их ранжирование

**Модель качества:** ISO/IEC 9126 (ГОСТ Р ИСО/МЭК 9126-93) выделяет **6 характеристик** качества ПО: функциональность, надёжность, практичность (удобство использования), эффективность, сопровождаемость, мобильность (переносимость). Каждая характеристика раскрывается **критериями** (подхарактеристиками).

**Метод ранжирования:** экспертная оценка значимости для данной КС (учётно-аналитическая система молочного производства: первичные документы, расчёты себестоимости, прогнозы, ИИ-рекомендации). Веса определены парным сравнением, сумма весов = 1.

**Таблица 1 — Ранжирование характеристик качества по значимости**

| Ранг | Характеристика (ISO 9126) | Вес | Обоснование значимости для данной КС |
|---|---|---|---|
| 1 | Функциональность | 0,30 | Система решает конкретные производственно-учётные задачи (учёт сырья, выпуска, брака, трудозатрат, прогнозирование, ИИ-аналитика). Полнота и корректность функций определяют ценность системы для заказчика. |
| 2 | Надёжность | 0,25 | Система оперирует первичными учётными данными и деньгами (себестоимость, стоимость брака). Потеря или искажение данных, сбои при проведении недопустимы. |
| 3 | Практичность (удобство использования) | 0,15 | Работают технологи, мастера смен, аналитики; важны понятный интерфейс Taxi, минимум действий в типовых операциях, наглядные отчёты и прогнозы. |
| 4 | Сопровождаемость | 0,15 | Конфигурация развивается (модели прогнозирования, интеграции, отчёты); важны модульность, тесты, читаемость кода, простота доработок. |

## 3. Измеряемые атрибуты по каждой характеристике

Для каждой характеристики приведены **измеримые атрибуты**: метрика, способ измерения и норматив (целевое значение). Измерения выполняются на контрольном примере: период — 1 год, номенклатура — 10–20 позиций, объём — до 100 тыс. движений регистров накопления.

### 3.1. Функциональность

| Атрибут (критерий) | Метрика | Способ измерения | Норматив |
|---|---|---|---|
| Полнота функций (соответствие) | K_ф = N_реализованных / N_требуемых × 100 % | Сопоставление функций конфигурации (5 документов, 5 отчётов, 2 обработки, модули прогнозирования и ИИ) с перечнем функций назначения системы | ≥ 95 % |
| Правильность расчётов | Погрешность Δ = \|X_факт − X_эталон\| | Юнит-тесты модуля UT_МолочногоПроизводства (ТестМНК, ТестEMA, ТестR2, ТестСКО, ТестСезонныйКоэффициент) + ручная сверка себестоимости и процента брака | точность до 0,01; тесты проходят 100 % |
| Защищённость | Доля объектов с настроенными правами; число нарушений матрицы доступа | Проверка матрицы ролей (Администратор / Аналитик); «негативные» тесты (попытка провести документ под ролью Аналитик должна приводить к отказу) | 100 % объектов покрыто; нарушений 0 |
| Взаимодействие | Доля успешных запросов к YandexGPT API; время ответа API | Прогон запросов модуля РаботаСYandexGPT, журнал регистрации | успешных ≥ 99 %; ответ ≤ 30 с |
| Соответствие стандартам | Число ошибок штатной проверки конфигурации | Конфигуратор → «Проверка конфигурации» | ошибок 0 |

### 3.2. Надёжность

| Атрибут (критерий) | Метрика | Способ измерения | Норматив |
|---|---|---|---|
| Отказоустойчивость (отказы проведения) | Доля отказов процедур ОбработкаПроведения = N_отказов / N_проведений × 100 % | Журнал регистрации; массовое перепроведение документов за период | < 0,1 % при корректных данных |

**Общие замечания и рекомендации (для развития системы и при составлении ТД):**
